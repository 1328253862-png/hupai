# 唬牌（本地定制版）· GitHub Pages

一个 2–6 人、朋友局用的纯前端联机唬牌游戏。大厅、房主权威状态、PeerJS + WebRTC 联机、手牌拖拽排序和移动端布局均已包含，不需要自建服务器或数据库。

## 运行

仓库根目录已经包含全部静态文件，可以直接双击 `index.html`，也可以通过任意静态 HTTP 服务打开：

```powershell
cd hupai
python -m http.server 8080
```

然后访问 `http://localhost:8080`。

页面会从 CDN 加载：

- Tailwind CSS 浏览器版：用于工具类。
- PeerJS 1.5.5：用于公共信令和 WebRTC 连接。

即使 Tailwind CDN 加载失败，本地 `css/styles.css` 也包含完整布局样式。PeerJS CDN 加载失败时无法创建或加入联机房间。

## 部署到 GitHub Pages

本仓库包含 `.github/workflows/pages.yml`。推送到 `main` 后，工作流会自动发布静态页面。

第一次发布时也可以在仓库中打开 Settings → Pages，把 Source 设置为 **GitHub Actions**。发布成功后地址通常是：

```text
https://1328253862-png.github.io/hupai/
```

如果 Actions 没有自动启用 Pages，进入 Settings → Pages，将 Source 改为从 `main` 分支根目录部署；本项目的 `index.html` 位于仓库根目录，不需要设置子目录。

## 部署到 Cloudflare Pages

1. 把仓库根目录作为站点根目录。
2. 在 Cloudflare Pages 中连接这个 Git 仓库，或直接上传该目录。
3. 构建命令留空。
4. 构建命令留空，输出目录选择 `/`。
5. 部署完成后用 HTTPS 地址访问。房主创建房间，其他玩家打开同一个地址，输入 6 位房间号加入。

也可以把同一份文件拖到任何支持静态托管的平台。托管平台只提供页面，联机仍通过 PeerJS 公共信令和玩家之间的 WebRTC 数据通道。

## 联机结构

- 房主浏览器保存完整权威状态、所有牌局逻辑和玩家手牌。
- 普通玩家只收到自己的手牌、公开玩家信息和桌面倒扣牌 ID，不收到其他玩家的手牌。
- 每个玩家只连接房主，房主最多连接 5 名其他玩家，然后向各玩家发送定制状态。
- 房间号映射为带命名空间的 PeerJS ID；ID 冲突时会自动换一个 6 位房间号重试。
- 房主网页关闭后，房间和本局状态无法恢复。

公共 PeerJS 服务可能出现限流或连接失败。部分严格 NAT、校园网或移动网络在只有 STUN、没有 TURN 的情况下也可能无法建立直连。朋友局建议先各自用手机网络和 Wi-Fi 测试；如果要提高公网可靠性，可以在 `js/config.js` 中替换信令配置，并增加 TURN 中继。

## 本版规则

- 2、小王、大王是万能牌。
- 新回合目标可选择 A、2、3–10、J、Q、K；王不能作为目标，但仍可作为万能牌使用。
- 一副牌单次最多出 4 张，两副牌最多 8 张。
- 掀牌时只能从 `lastPlayer` 最后一次出的牌中手动选择，上一手不超过 4 张选 1 张，超过 4 张选 2 张。
- 选中牌中只要有一张既不是目标、也不是万能牌，就视为掀牌成功。
- 玩家打出最后一手后进入“待定获胜”：顺时针下一位只能掀牌或过牌。过牌则最后一手获胜；质疑失败仍由最后一手玩家获胜；质疑成功则玩家收牌，质疑者开启新一轮。
- 有人手牌降到 3 张时，房主开启报备开关会向全桌公开播报。
- 玩家掉线有 10 秒重连窗口；超时仍未恢复则本局结束。房主关闭页面则整个房间结束。
- 游戏结束后，房主返回等待房间，可以修改 2–6 人的最大座位数；新朋友可以重新入座补位。
- 发牌后手牌会自动按点数组好，同点牌向上叠放并露出点数和花色；一副牌同一牌摞最多 4 张，两副牌最多 8 张。等待别人操作时可以拖动整摞调整位置，也可以点“一键理牌”。轮到自己出牌时会暂时锁定整理；单击选牌，在第一张牌上按住并拖动可以连续选牌。
- 鼠标位于手牌区域时，滚轮横向浏览手牌；移出手牌区域后恢复页面正常上下滚动。

## 已知边界

这是朋友局实现，不做账号登录、排行榜、服务端持久化或强反作弊。房主本身持有完整牌局状态，因此无法在纯前端架构下阻止房主查看或修改自己的浏览器数据。房间号也不是强权限凭证。
